# OpenFrame 0.26.0

This milestone adds **Split header** as a selectable style for live data widgets. Metric, radial gauge, sparkline, mini-table, and channel breakdown cards share the blue/navy headers, white or Sky Blue bodies, yellow comparison pills, and optional footer labels. Main values use full-size decimal digits with tightly positioned raised currency prefixes and units. Existing widgets retain Classic until their style is changed.

Radial gauges are centered, with compact goals in the bottom-right corner. Their scale maximum is independent of the goal. Line cards can enable **Show min / avg / max** to display statistics for the current series snapshot in place of date labels, preserving the plot area. The average is the arithmetic mean of the supplied samples. Statistics and comparisons update through normal feed sync without replacing the active slide. Mini-table comparison rows match by category label.

The editor and shared player **0.12.0** use the same bounded SVG renderer, without a new charting dependency, network request, animation, or timer. Card settings are validated against fields in the selected feed; changing feeds clears comparison bindings. See [card setup](../widget-cards.md) for the controls and examples.

## Upgrade and rollback

Back up the complete database/media volume before upgrading. Pull the versioned 0.26.0 server image or the successfully published `latest` image, then recreate the container while preserving its data volume and Compose project name. Updating an image does not update a running server automatically.

Install player **0.12.0** for the complete card appearance and statistics. Android APK updates retain the existing signing key and require installation confirmation. Pi installations need the updated agent and complete `player/web/` directory, including `data-cards.js`. Server replacement alone does not update installed player code.

Manifest schemas, feed ingestion payloads, sync, permissions, and cached snapshot handling are unchanged. Older data-capable players before 0.11.1 retain Classic primary-value rendering; players 0.11.1–0.11.4 can render cards but ignore the statistics option. Updated players still accept older publications. Data-only playlists continue using schema 4; video playlists use schema 5.

To roll back to server 0.25.0, restore the pre-upgrade backup with its matching image. That server does not accept the optional `card` settings when saving edited slides. Save any new content separately before restoring the backup. Updated players remain compatible with the older server. Image rollback alone does not revert saved slide changes.

## Verification and publication

Local Node/Python, Chromium editor/player, Android native, lint, TypeScript, and production-build checks cover the card renderer, settings persistence, live statistics, safety, and existing playback. The release validation record lists the final checks. Device checks on physical Onn/Pi hardware remain outstanding; desktop/JVM tests do not establish display performance or unattended reliability.

The approved version tag runs hosted CI and native AMD64/ARM64 container checks before publishing the versioned server image and its `latest` alias. The player version change on `main` separately triggers signed Android publication. Check the [workflow results](https://github.com/veRoduS/OpenFrame/actions) before assuming either the latest image or latest APK has advanced. These workflows do not deploy onto a running server or install the APK on a TV.
