# OpenFrame 0.32.0

This server/web milestone raises the default feed field limit from 20 to **100** and adds **Settings → Data feeds → Feed limits** for administrators to select **1–500 fields per feed**. Changes take effect immediately and persist across server restarts.

The setting applies to manual feed creation, per-store application ingestion and central multi-store SMCC batches. Lowering the limit preserves existing fields and stored data; wider feeds continue accepting value updates and can be renamed. Additional fields and new feeds must fit the current setting. Central batch failures still roll back every store in that request.

The byte limits remain 32 KiB per single-store request or central metrics/tables section, and 256 KiB per central batch. Table rows, graph points, ingestion rates, total feed counts and playlist feed counts retain their existing limits. Raising the field limit does not automatically combine numbered sources: SMCC chooses which source receives each field. See the updated [SMCC developer handoff](../smcc-integration-update.md).

## Compatibility and upgrade

Server **0.32.0** remains compatible with player **0.15.5**. No new APK is required. The server continues sending complete referenced feeds to players. Selective metric delivery is an assessed follow-up and is not included in this release. Existing ingestion endpoints, application/feed keys, manifests and snapshot formats remain supported.

Back up the complete persistent data volume before upgrading and preserve the Compose project name and volume. Deploy `ghcr.io/verodus/openframe:0.32.0` or the published immutable digest, then recreate the server container with the existing configuration. The field limit defaults to 100 on first use; an explicitly saved setting is preserved. There is no automatic feed deletion, merging or widget rebinding.

After verification, this milestone publishes AMD64/ARM64 images under `0.32.0` and `latest`, and a latest GitHub Release with a digest-pinned Compose ZIP. The source `latest` marker points to this release commit. Source/image publication does not update a running installation. To roll back, restore the matching pre-upgrade data backup and previous image digest.

## Verification and acceptance

The feature revision passed 281 Node tests, 101 Python tests and three Chromium flows covering limit settings, central multi-store feeds and live data widgets. The feed suite also verifies default/range enforcement, persistence, wider-feed preservation, atomic failures and 100-field publication, preview and player sync. Publication CI validates the exact tagged source, native AMD64/ARM64 containers and Android JVM compatibility before image publication.

This release is experimental for physical-device acceptance. Physical TV/Pi playback performance and a production SMCC connection have not been validated for this milestone; desktop and container checks do not establish hardware performance.
