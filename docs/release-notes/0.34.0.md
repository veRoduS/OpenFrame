# OpenFrame 0.34.0

This server milestone releases the redesigned public landing page. It includes
the previously local server revision 0.33.1. The player is unchanged at 0.15.10.

## Changes

- Redesign the public homepage at `/`. The display in the opening photograph
  plays a fictional four-slide sample playlist drawn by the page, and the same
  playlist plays on the screens of the network diagram. One timer advances it
  only while the page is visible; a control pauses it or selects a slide.
  Visitors who prefer reduced motion start paused, with no transitions.
- Replace the workspace screenshot with three captures of the current
  management UI: the slide editor, a playlist sequence and a screen card, all
  made from fictional sample data.
- Set headings in Fraunces and text in Figtree. Both are bundled with the build
  under the SIL Open Font License 1.1; the page still requests nothing from the
  installation's API or from any other origin.
- Add first-run steps beside the install commands, and show the server address
  to enter in the Android player, or an example when the page is opened through
  a loopback address.
- Run the Chromium browser regression job on Ubuntu 24.04, where the pinned
  Playwright release can install its browser.

## Compatibility and upgrade

- Only the public page changes. Sign-in, `/dashboard`, the server API and the
  manifest, sync and update contracts are unchanged; no player update is needed.
- Stop the server and back up its complete data volume before upgrading. Deploy
  the versioned image or attached digest-pinned Compose bundle, preserving that
  volume.

## Rollback and validation limits

Keep the previous server image. This release changes no stored data, so rolling
back to 0.33.0 needs only the previous image; a data-volume backup remains the
general precaution.

The landing browser suite covers six viewport widths from 1920 to 320 pixels,
both motion preferences, cross-origin requests and the existing sign-in flows.
It ran in Chromium only: Safari, Firefox and physical phones were not tested.
This release does not establish Pi or Android TV behaviour and does not
automatically deploy to an existing server.
