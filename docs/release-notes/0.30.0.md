# OpenFrame 0.30.0

This release brings the accumulated changes since the last GitHub release,
0.25.0, into a published server image. Android/Pi Player **0.15.5** is already
available as a [signed APK](https://raw.githubusercontent.com/veRoduS/OpenFrame/android-releases/apks/0.15.5/openframe-player.apk).

## Locations, screens and metrics

- Assign application API keys and metric sources to sites, and enter a site
  number during player enrollment. Any authorized member of the store's access
  group or a subgroup can approve its new screens with the pairing code.
- Reuse layouts across stores. Data widgets list each store source once and
  follow the screen's assigned store by default. Administrators can still pin
  a widget to a particular source when needed.
- Set access groups for sites, move screens through reviewed transfers, and
  assign existing integrations without replacing their credentials. Site
  transfers acknowledge a cleared player cache before receiving replacement data.
- Create application/feed API keys with an expiry date or **Never expires**,
  and change an existing key's expiry without rotating its secret. Revocation
  remains available.
- Filter Slides, Playlists and Screens by group. Administrators other than the
  built-in `admin` account can choose an optional home store/group and switch
  between Home and Admin visibility. Accounts without a home keep their existing
  workspace.

## Slides and playback

- Skip individual entries in a forked playlist and restore them later. Skips
  remain local to the fork, survive master updates, and reach screens when
  published. Repeated copies of a slide can be skipped independently.
- Authorized slide sharers can share upward to parent groups without changing
  the slide's managing group. Embedded images remain read-only for recipients.
- Image uploads no longer have a megapixel cap. The existing **15 MB** file
  limit and optimized WebP output bounds remain. Video limits are unchanged.
- Use **Forecast card** for full-width hourly weather rows, with a compact
  layout for narrow cards. Existing Horizontal/Vertical weather layouts remain.
- SMCC/category tables support up to **100 rows**, including row ranges and
  matching deltas. Card typography, group arrangement, row-range visibility,
  goal colors and configured header/border refinements from the 0.26–0.29
  milestones are included.

## Upgrade and rollback

Back up the complete database/media volume and record the current image digest.
Use the attached digest-pinned Compose bundle, or select
`ghcr.io/verodus/openframe:0.30.0` (or the successfully published `latest` image),
pull it, and recreate the server while preserving its Compose project name and
data volume. For HTTPS, keep the exact browser-facing `PUBLIC_URL` and
`COOKIE_SECURE=true`. Never delete the data volume during an upgrade.

The image workflow publishes native **AMD64** and **ARM64** variants. ARM64
requires a 64-bit OS. Publication does not update a running server automatically.

Update affected Android/Pi players to **0.15.5** before using Forecast card or
tables/ranges beyond 40 rows. Existing players continue using their installed
code; a server update alone does not update them. Android installation requires
user approval and the existing release signing key. Existing layouts and smaller
tables remain supported. Skipped fork entries are flattened by the server and
need no player upgrade. Legacy unassigned screens and integrations keep their
existing workflow. See [server/player compatibility](../player-compatibility.md)
and the [developer API update](../api-update-multi-site.md) for upgrade details.

To roll back, select the previous image digest and restore the matching
pre-upgrade backup into a separate volume. Keep the newer installation and data
available until rollback is verified; an older image alone does not undo schema,
site or configuration changes. Keep newer players installed when possible, and
remove unsupported content before deliberately downgrading player code.

## Validation and acceptance

The milestone image pipeline gates publication on Node/Python regressions,
typecheck, lint, repository/version/compatibility checks, dependency audit,
Chromium regression suites, Android JVM tests, and native AMD64/ARM64 container
startup, image-codec and data-persistence checks. The signed 0.15.5 APK passed
the publishing workflow and independent checksum/certificate verification.

Physical TV/Pi installation, long-running playback and hardware performance
remain **experimental**. Automated checks do not establish physical-device
acceptance. Test a representative screen before a fleet rollout.
