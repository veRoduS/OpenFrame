# OpenFrame 0.19.0

This server release adds inherited read-only access, linked playlist forks, and folders and tags for larger slide and playlist libraries.

- Managing groups control editing. Inherited hierarchy access is View; explicit Edit grants can enable collaboration. Global admins retain unrestricted access.
- A local group can fork a master playlist, add slides, and override timing, speed, and order. Master publications update the fork while preserving its published local changes. Unpublished fork drafts remain unpublished; forks do not change their master or sibling playlists.
- Slides and Playlists have separate nested folders and tags, drag/drop moves, bulk organization, and combined filters. Folder placement does not grant content access.
- Slide insertion controls are separated into Content and Widgets.
- Express's transitive proxy-addr dependency is updated to 2.0.8 for GHSA-jqcg-44mw-7w3h.

## Upgrade and access migration

Player **0.10.12 remains compatible and unchanged**. Linked forks are resolved by the server into ordinary schema 2/3 playlist publications. This release does not require a new APK or change Android display/sleep behavior. Play Store distribution remains a proposal, not an implemented feature.

Existing direct access grants retain Edit. Access inherited through the group hierarchy becomes View. Review existing direct grants and configure managing groups when adopting the new model; an old explicit Edit grant continues to permit editing even when that person also inherits View. Existing credentials, sessions, player tokens, content, and publications are preserved.

Before upgrading, stop the server and back up its complete data directory or volume. Preserve the Compose project name, volume, PUBLIC_URL, COOKIE_SECURE, and player pairing. Never use `down -v` for an upgrade. Once the release image is published, installations following `ghcr.io/verodus/openframe:latest` can pull and recreate the server using their existing Compose file and project arguments:

```sh
docker compose -f compose.registry.yaml pull
docker compose -f compose.registry.yaml up -d
```

Deployment is not automatic. Check representative users' View/Edit access, publish a sample master/fork, and verify a screen after upgrading. See [linked playlists](../linked-playlists.md) and [View and Edit permissions](../users-and-groups.md#view-and-edit).

For rollback, stop the new server, restore the complete pre-upgrade backup, and select the previous image digest/version using the same Compose project. Older servers do not understand the new permissions and fork metadata; restoring only an older image against the migrated database is not a supported rollback. See [operations](../operations.md).

## Validation and limits

Local validation and remaining limits are recorded in [the validation record](../validation.md). The tagged workflow independently verifies the exact source and native AMD64/ARM64 container behavior before publishing the versioned and latest images. Physical Pi/Android playback and performance were not retested for this server revision.
