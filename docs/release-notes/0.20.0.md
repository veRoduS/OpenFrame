# OpenFrame 0.20.0

OpenFrame now accepts live data from external integrations and displays it in reusable metric, progress, line graph, and bar chart widgets. Feed updates reach active slides through normal sync without republishing or restarting the slide.

## Data feeds and widgets

Create a feed under **Data feeds**, define number, time-series, or category fields, and issue a scoped write-only token. Tokens expire, can be revoked, and stop working when their creator loses active Edit access. Payloads are validated and bounded; each feed stores its latest complete snapshot, with a maximum of 60 authorized update attempts per minute.

In the slide editor, choose a data widget and bind its feed and field. Progress supports a fixed target or another numeric field and horizontal/vertical layouts. Titles, units, decimals, colors, update-age labels, and stale thresholds are configurable. Charts scale with their boxes and use automatic axes. Players retain cached data through offline restarts and clear inaccessible values following a successful online sync.

Feeds follow existing group View/Edit rules, including view-only hierarchy inheritance and unrestricted admin access. Slide/playlist sharing and publication checks validate feed dependencies. The Data feeds page links the [standalone API guide](../data-feeds-api.md) and [OpenAPI contract](../../server/data-feeds.openapi.json); **Copy integration details** bundles the feed's schema, update URL, and documentation links. A [Python client](../examples/push-data-feed.py) is included.

## Upgrade order and data preservation

Back up the existing SQLite database and media using the normal server backup process, and preserve the data volume during upgrades. Feed tables are added without replacing users, groups, media, or existing publications.

Upgrade the Android app or complete Pi player to **0.10.13+ before assigning playlists with data widgets**. These playlists use manifest schema 4. Earlier players reject the new schema and retain their last usable cached publication. Existing playlists retain schemas 2/3, and the new player still accepts schemas 1–3 against older servers. Server and player versions remain independent.

Android updates use the existing release signing key and preserve pairing and content when installed over the app. Android requires the user's installation approval. Server/image publication does not update a running server or installed player automatically.

## Verification

The implementation passes 188 Node tests, 92 Python tests, and 28 native Android agent/updater tests, plus data-feed/live-rendering and library-access browser checks. Coverage includes token expiry/revocation, payload limits, inherited access, publication dependencies, live updates without frame replacement, offline restart, and clearing revoked data after reconnecting. Browser layouts were checked at desktop and phone widths. Lint, typecheck, production build, version/repository checks, and the explicit compatibility review pass.

The release workflow additionally verifies native AMD64/ARM64 containers and the signed APK before publication. Desktop/JVM checks do not establish physical TV/Pi performance or long-run hardware acceptance.
