# OpenFrame 0.22.0

All signed-in users now see the same nested folder navigation on Slides, Playlists, and Media, including empty folders. Only admins can create, rename, move, delete, or manage access to folders. Users can move content they can edit into any folder. Folder visibility does not grant access to its contents, and folder moves do not alter content permissions. Legacy folder ownership or Edit grants do not override the admin requirement.

Multiple media uploads now appear in a persistent bottom-right progress panel. Each file shows transfer progress, processing, and a confirmed result. Files upload sequentially; one failure does not stop the rest. The panel remains when switching pages. Cancellation stops queued files and active transfers; an image already processing finishes and is confirmed. The batch keeps the destination chosen when it started.

Slides, Playlists, and Media tagging forms offer existing tags alongside typed comma-separated tags. Select several existing tags, add new ones, or choose existing tags for bulk removal. Choices come from visible content in the current library, and tags already entered are excluded from the picker.

The playlist editor's **Add slides** grid now scrolls large libraries instead of compressing their rows. Landscape, portrait, and square previews retain their proportions and readable labels at desktop, laptop, and phone sizes.

Sharp is updated to **0.35.5**, with its patched native image libraries, to address [GHSA-wq5f-xc86-pv6w](https://github.com/advisories/GHSA-wq5f-xc86-pv6w). The final production dependency audit reports no known vulnerabilities.

## Upgrade and rollback

Preserve the existing data volume and back up the database and media before updating the server image. Use the normal image-update process with the versioned image or `latest`. The running server changes only after its container is recreated with the updated image. To roll back, select the previous 0.21.0 image while retaining the same data volume; restore the backup if needed.

There is no database migration or new player protocol. Existing accounts, grants, tags, folders, media URLs, and published playlists remain usable. Content permissions continue to apply independently of folder visibility.

The player remains **0.10.13**; no new APK is needed. Playlists with data widgets still require player 0.10.13+, and existing publications retain their supported manifest schemas.
