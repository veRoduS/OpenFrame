# OpenFrame 0.23.0

Workspace pages now use consistent search, filters, result counts, sorting, view controls, and actions. Section and filter URLs survive reload and browser Back. Mobile navigation closes when a section is selected. Loading, retry, and empty states distinguish a failed request from an empty library.

Slide and playlist editors use clearer panel names, labeled insertion controls, consistent dialogs, and visible mobile actions. Playlist cards distinguish Draft, Published, and Unpublished changes. Draft and published previews show the selected version, and slide saves explain which published playlists and screens will update. Screen status separates connection from reported playback; Add screen guides users through pairing, Android, or Pi/Linux setup, with advanced network controls available separately.

Settings—including Data feeds, Stock quotes setup, and Fonts—is available only to admins. Direct Settings links redirect non-admins to Slides, and feed setup and API-key management require an admin session even when a user has feed Edit access. Users retain shared feed and font use in slide editors. Existing integration keys and bearer snapshot updates continue working under their existing permissions.

Slides and Playlists checkboxes now retain a visible green fill and white checkmark when selected, including after focus moves, search changes, or a different slide layout is selected.

New slides mark their initial “Something worth\nsharing.” text layer. Publication removes this layer only if its text was never edited. Existing unmarked layers and edited layers are retained. Cleanup changes editable source slides and their publications transactionally; sources the publisher can only view are preserved, while the untouched starter is excluded from their published snapshot.

## Upgrade and rollback

Back up the complete database and media volume before updating. Pull the versioned 0.23.0 image or the updated `latest` image, then recreate the server container while preserving its data volume. Image publication does not update a running server automatically.

Accounts, permissions, folders, tags, media URLs, and existing publications remain usable. No database migration or new player manifest schema is required. Regular users who previously managed feed setup must now ask an admin to make those changes.

Publishing may permanently remove untouched marked starter layers from source slides. Rolling back the image does not restore those layers; restore the pre-upgrade backup if that is needed. Otherwise select the previous 0.22.0 image through the normal image-update process.

The player version is 0.10.14 for published-preview support. Existing installed players continue working with supported schemas and do not need updating for these server UI changes. Data widgets still require player 0.10.13 or newer. Physical Pi/Android playback performance has not been revalidated for this milestone.
