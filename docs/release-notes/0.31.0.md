# OpenFrame 0.31.0

This server/web milestone adds one SMCC application with a central key for selected stores, atomic multi-store metric/table updates, and feeds grouped by integration and store. Shared layouts continue to show each screen's local values. Existing per-store application and feed-specific APIs remain supported.

- Generate a **Multiple stores (central)** key under Settings → Data feeds → Applications → Manage keys. Select the existing stores it may update; future stores require a replacement key with an updated selection.
- Send `POST /api/data-feeds/ingest-stores/:sourceKey` with store-numbered `metrics` and `tables` sections. A batch succeeds or rolls back together. See [the SMCC developer handoff](../smcc-integration-update.md) for the payload, limits, errors and retries.
- Delete/reset data connections while keeping widget positions, formatting and settings. The reviewed reset removes application/feed keys and stored values, disconnects drafts and published snapshots, and leaves layouts available to reconnect later. Existing delete guards remain unless disconnection is explicitly requested.
- Publish **Follows each screen’s store** widgets across isolated store groups without requiring access to the example store's data. Fixed-feed recipient checks remain enforced.

## Compatibility and upgrade

Server **0.31.0** remains compatible with player **0.15.5**. No new APK is required for this server update. Player manifests and data snapshots retain their existing contracts. Existing credentials migrate without replacing their hashes, and existing single-store keys keep their original endpoint and namespace. New central keys work only with the multi-store endpoint.

Deploy the server before switching SMCC to the new endpoint. The application-token table gains a nullable store-selection column automatically. Back up the complete persistent data volume before upgrading and preserve the Compose project name and volume. Connection reset is an explicit operator action; upgrading does not delete connections or widgets.

After the image workflow succeeds, pull `ghcr.io/verodus/openframe:0.31.0` (or its immutable digest) and recreate the server container using the existing configuration. The workflow also advances the container image's `latest` alias; pushing source does not update a running server. To roll back, restore the matching pre-upgrade database backup and previous image digest.

## Verification and limits

The included feature revision passed 278 Node tests, 101 Python tests and five Chromium flows covering central key setup, grouped store feeds, retained widget reconnection, existing application keys, connection reset, live widgets and 100-row tables. Publication CI additionally checks the tagged source and native AMD64/ARM64 containers before publishing both image architectures.

Physical TV/Pi playback and a production SMCC connection have not been tested for this milestone. This is an experimental release for hardware acceptance; automated desktop/container checks do not establish physical-device performance.
