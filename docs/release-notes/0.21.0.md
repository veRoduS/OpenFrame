# OpenFrame 0.21.0

Slides and Playlists now use the same folder sidebar as Media. Nested folders have indentation, collapsible branches, and item counts. Drag items into folders, move folders into other folders or back to the top level, and edit the selected folder from the content header. Phones use the same mobile folder picker as Media. Folder and tag changes preserve content permissions and published playback.

Data feeds now live under **Settings → Data feeds**. Existing feed View/Edit permissions remain in effect, including non-admin management of editable feeds and view-only inherited feeds. Stock and font configuration remains admin-only.

Generate a separate **API key** for each application updating a feed. The one-time pop-up provides the key and exact update URL, and the feed dialog provides copyable request examples and integration details. Applications send complete JSON snapshots using `PUT` and `Authorization: Bearer YOUR_API_KEY`, without logging into OpenFrame. Keys remain write-only, feed-specific, expiring, and revocable. Existing keys, `/tokens` management endpoints, and the `token` response field are unchanged.

The [API handoff guide](../data-feeds-api.md) and [user guide](../user-guide.md) document the updated setup.

## Upgrade and compatibility

Preserve the existing data volume and use the normal database/media backup process before updating the server image. This release introduces no database migration, new player protocol, or manifest change. Existing feeds, API keys, accounts, group permissions, folders, and publications remain usable.

The player release remains **0.10.13**. No new Android APK is required for these UI changes. Playlists containing data widgets still require player 0.10.13+; existing playlists keep their previously supported schemas. Updating the published image/tag does not itself update a running server.

## Verification

188 Node tests and 92 Python tests pass, along with production build, lint, typecheck, version, compatibility, repository, and shell syntax checks. Browser checks cover nested folders in both libraries, drag/drop, renaming, desktop/390px/320px layouts, non-admin inherited/editable feeds under Settings, one-time key display, unauthenticated application updates using a generated key, live widgets, and general UI layout.

The publication workflow additionally verifies native AMD64 and ARM64 containers before publishing images. These checks do not establish physical-player or long-run hardware performance.
