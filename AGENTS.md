# Working on OpenFrame

- Keep ordinary source work local. Do not push source branches/tags, create a GitHub repository/release, publish packages/images, or run a deployment unless the owner explicitly authorizes that milestone. The owner has separately authorized signed Android APK publication to `veRoduS/OpenFrame`'s `android-releases` branch under `apks/`; this does not authorize pushing source history.
- Each completed logical revision or bug fix gets one patch bump and a changelog entry for each changed component: `pnpm version:patch "Summary"` for the server/web app, `pnpm version:player:patch "Summary"` for the Pi/Android player. Do not bump an unchanged counterpart, once per file, intermediate retry, or review correction within the same revision.
- Only an explicitly approved GitHub milestone gets a minor bump: `pnpm version:milestone --milestone-approved "Milestone summary"` for the server or `pnpm version:player:milestone --milestone-approved "Milestone summary"` for the player. This resets the changed component's patch to zero. Approval flags are safeguards, not permission to approve your own release.
- Major releases are reserved for an explicit owner request: `pnpm version:major --major-approved "Major release summary"` or the `version:player:major` equivalent. Never infer major-release approval from scope or breaking changes.
- Use the version scripts, not `npm version` or manual edits. `package.json` is canonical for the server; `player/version.json` is canonical for the shared player, synchronized to the Pi agent by the tool and read directly by Android builds. Their versions may drift. Manifest schemaVersion and playlist publication revisions are independent.
- Run `pnpm compatibility:check` after contract-related changes. Review their effect on the other component and record the tested compatibility or required upgrade in `compatibility.json` using `pnpm compatibility:review --impact compatible|breaking "Summary"`; never auto-refresh this record just to pass a check. See [server/player compatibility](docs/player-compatibility.md).
- `pnpm build:android` builds and publishes by default; use `--local` for a local-only APK and `pnpm publish:android` to retry an upload. Publication requires clean, committed source and a current compatibility review. Preserve the signing key and immutable version archives; never force-push or upload source/secrets with the APKs.
- A local commit is not a GitHub push. Preserve local patch commits; publish their accumulated history only with the approved milestone. Never squash, reset, or force-push without permission.
- Read [CONTRIBUTING.md](CONTRIBUTING.md) and [the release checklist](docs/releases.md). Run version/repository checks, Node and Python tests, lint, typecheck, and build before calling a milestone ready.
- Never commit real media, databases, credentials, provisioning JSON, configured disk images, caches, or generated build output to source branches. The dedicated Android publication branch contains only signed APKs and public release metadata. Use example configurations containing placeholders only.
- Keep player resource use bounded: one visible/one prepared frame, timers only while visible, disposal on cancellation. Do not claim Pi performance from desktop tests.
- Update user/deployment/API documentation when behavior changes. Preserve existing user data and worktree edits. Android supports update checks and user-confirmed APK installation; no unattended player-code/OS update service exists.
